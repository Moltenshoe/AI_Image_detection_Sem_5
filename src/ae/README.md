# Block 2 — Autoencoder (AE) Data Interface

## 1. Overview and Rationale

This module provides the independent data-loading infrastructure for the Autoencoder (AE) pathway in Block 2.

In Block 3, we will implement and train two separate Convolutional Autoencoders (CAEs):

1. **Real Autoencoder:** Trained exclusively on authentic images (`Label_A == 0`).
2. **AI Autoencoder:** Trained exclusively on AI-generated images (`Label_A == 1`).

### Why Two Separate Autoencoders?

When an autoencoder is trained exclusively on a single distribution (e.g., real images), it learns an internal manifold optimized for compressing and reconstructing samples from that distribution. When presented with out-of-distribution inputs (e.g., synthetic AI images generated by diffusion or GAN models), its reconstruction fidelity degrades because the novel spatial and textural artifacts cannot be faithfully represented by the learned latent bottleneck.

By training two class-specific autoencoders—one on real images and one on AI-generated images—we obtain two distinct reconstruction error signals:
$$\Delta_{\text{real}}(x) = \|x - \text{Dec}_{\text{real}}(\text{Enc}_{\text{real}}(x))\|$$
$$\Delta_{\text{ai}}(x) = \|x - \text{Dec}_{\text{ai}}(\text{Enc}_{\text{ai}}(x))\|$$

The asymmetric reconstruction differential:
$$S_{\text{diff}}(x) = \Delta_{\text{real}}(x) - \Delta_{\text{ai}}(x)$$
serves as a powerful, interpretable detection metric for downstream classification.

## 2. Shared Evaluation Protocol

While the two autoencoders are trained on disjoint image classes:
- Real AE training: `label_a == 0` only (7,000 samples)
- AI AE training: `label_a == 1` only (35,000 samples)

**Both models must be evaluated on the exact same validation and test images**, covering both real and AI-generated samples.

To support this requirement, the module implements:
- `AEDataset(class_filter=None)`: A general-purpose dataset loading the full validation (9,000) or test (45,000) split with both classes.
- Full cross-class evaluation matrix:
  * Real AE evaluated on real validation images (`class_filter="real"`).
  * Real AE evaluated on AI validation images (`class_filter="ai"`).
  * AI AE evaluated on real validation images (`class_filter="real"`).
  * AI AE evaluated on AI validation images (`class_filter="ai"`).
  * Both evaluated on the shared mixed evaluation set (`class_filter=None`).

Neither autoencoder is restricted in evaluation to its training class.

---

## 3. Preserving Training Set Distribution

The Block 1 training split contains:
- Real images (`label_a == 0`): **7,000**
- AI images (`label_a == 1`): **35,000**
- Total: **42,000**

In accordance with scientific controls:
- No AI images are discarded or subsampled at the data interface level.
- All available training samples are preserved initially.
- The interface enables Block 3 training code to log and monitor optimizer steps, epoch counts, loss convergence curves, and the number of image presentations for each model.
- Training fairness, class balance strategies, and convergence criteria will be evaluated systematically in Block 3.

---

## 4. Zero Redundant Persistent Datasets

No redundant persistent image datasets or derived image copies are created on disk. Temporary in-memory arrays and tensors required for loading are permitted.

The data interface reads directly from existing Block 1 canonical images:
- **Training split (`split="train"`):** Reads pre-decoded uint8 RGB arrays from `data/processed/train/part-*.parquet` (materialized per DEC-009/DEC-010).
- **Validation and test splits (`split="validation"`, `split="test"`):** Reads dynamically on-demand from raw Parquet files (`data/defactify/data/validation-*.parquet`, `test-*.parquet`) using the canonical preprocessing function `src.data.preprocessing.preprocess` (DEC-008, DEC-009).

Both paths share identical spatial preprocessing contracts:
1. Centered largest square crop.
2. Area-based resizing (`cv2.INTER_AREA`) to 256×256.
3. RGB float32 tensor conversion in `[0.0, 1.0]`.

---

## 5. Sample Identity & Metadata Preservation

The module strictly preserves the original Block 1 sample identity:
- `sample_idx`: 0-indexed integer corresponding to the sample's position in the original Block 1 split.
- `image_id`: Canonical stable string identifier formatted as `{split}_{sample_idx:06d}` (e.g. `train_000000`, `validation_000000`, `test_000000`).

When filtering by class (e.g. `RealAEDataset` filtering 7,000 real images out of 42,000), each sample retains its original `sample_idx` and `image_id` from the full split. This ensures 1:1 cross-pipeline alignment with the Forensics Feature Bank (`src/forensics/`) and the RGB Local Representation Pipeline (`src/rgb/`).

## 6. Block 3 Consumption Example

Downstream Block 3 training and evaluation scripts consume the interface as follows:

```python
from src.ae import (
    create_real_ae_loader,
    create_ai_ae_loader,
    create_ae_eval_loader,
)

# 1. Training Loaders (class-exclusive, shuffle=True)
real_train_loader = create_real_ae_loader(
    split="train",
    batch_size=32,
    num_workers=4,
)

ai_train_loader = create_ai_ae_loader(
    split="train",
    batch_size=32,
    num_workers=4,
)

# 2. Shared Evaluation Loader (both classes, shuffle=False)
shared_val_loader = create_ae_eval_loader(
    split="validation",
    class_filter=None,
    batch_size=32,
    num_workers=4,
)

# 3. Class-specific Evaluation Loaders (cross-class testing)
real_val_loader = create_ae_eval_loader(
    split="validation",
    class_filter="real",
    batch_size=32,
)
ai_val_loader = create_ae_eval_loader(
    split="validation",
    class_filter="ai",
    batch_size=32,
)
```

Each batch yields `(images, labels, metadata)`:
- `images`: Tensor `[batch_size, 3, 256, 256]`, float32, in `[0.0, 1.0]`.
- `labels`: Tensor `[batch_size]`, int64 (0 for real, 1 for AI).
- `metadata`: Dict with `"sample_idx"` (Tensor of ints) and `"image_id"` (list of strings).
